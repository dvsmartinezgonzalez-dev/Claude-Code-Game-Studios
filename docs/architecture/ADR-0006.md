# ADR-0006: Board State Representation and Game State Manager Design

## Status

2026-05-02

## Summary

GSM must be the sole authoritative owner of board state and must guarantee that every downstream system (Sort Mechanic, Animation System, HUD) always reads a consistent, fully-committed view. This ADR defines the board state data model, the atomic 5-step mutation contract, the watchdog timer, the monotonic sequence ID, the lifecycle FSM, and the `IGameStateManager` public interface that implements these invariants.

## Context

### Problem Statement

BoltSort's core loop requires six systems (Sort Mechanic, Animation System, HUD, Level Progression, Hint System, Tutorial System) to read board state reliably. Without a single authoritative owner, each system would maintain its own copy of board state, which would diverge under undo, watchdog recovery, and background/foreground app lifecycle transitions. GSM must be designed before any gameplay system can be implemented.

### Current State

No board state system exists yet. This ADR establishes it from scratch.

### Constraints

- Unity 6.3 LTS, C#, mobile (iOS + Android)
- Board state must be readable synchronously on the main thread — no async board reads
- Coroutines run on the main thread; watchdog must use `WaitForSecondsRealtime` so it fires during pause (`Time.timeScale = 0`)
- Mobile memory ceiling: 512MB — board arrays are small (≤ 11 stacks × ≤ 8 bolts = 88 ints); no concern

### Requirements

- TR-GSM-001: GSM is sole owner and writer of board state arrays
- TR-GSM-002: `CurrentSequenceId` is monotonically increasing; never decrements
- TR-GSM-003: Unlimited undo stack during ACTIVE; frozen on COMPLETE
- TR-GSM-004: Watchdog timer 1500ms fires `OnBoardRefreshForced` if `OnMoveExecutingExited` does not arrive
- TR-GSM-005: Atomic 5-step board mutation — all steps execute synchronously in one frame
- TR-GSM-006: Deferred undo during MOVE_EXECUTING — stored and processed on exit
- TR-GSM-007: Bolt-count invariant check at level load (L-03)
- TR-GSM-008: Level lifecycle FSM — UNLOADED → LOADING → ACTIVE → COMPLETE → TEARDOWN → UNLOADED

## Decision

**GSM is the sole writer of board state.** All board state lives in private `List<int>[]` arrays inside `GameStateManager`. External systems access board state only through `IReadOnlyList<int>[]` properties on `IGameStateManager`. No external system may write to `_stackContents` or `_tempSlotContents`.

**Flat namespace.** Color stacks occupy indices `0..(colorCount-1)`. Temp slots occupy indices `colorCount..(colorCount+tempSlotCount-1)`. This flat namespace is consistent across undo entries, the Sort Mechanic read interface, and all event payloads.

**Atomic 5-step mutation.** On every `move_committed` event, all five mutation steps execute synchronously on the main thread within a single method call, with no `await` between steps.

**Monotonic `long` sequence ID.** `CurrentSequenceId` starts at 0 at level load and increments on every board state mutation (move commit, undo, watchdog fire, foreground restore). It never decrements. Typed as `long` (int64) per EC-12.

**Coroutine watchdog.** A `WaitForSecondsRealtime(1.5f)` coroutine starts after each `move_committed`. If `OnMoveExecutingExited` does not arrive within 1500ms, the watchdog fires: increments `CurrentSequenceId` and emits `OnBoardRefreshForced`. The timer is cancelled on every MOVE_EXECUTING exit path.

**Lifecycle FSM.** UNLOADED → LOADING → ACTIVE → COMPLETE → TEARDOWN → UNLOADED. `LoadLevel` is rejected silently in any non-UNLOADED state.

### Key Interfaces

```csharp
public interface IGameStateManager
{
    // ── Board State (read-only, synchronous pull) ──────────────────────────
    IReadOnlyList<int>[] StackContents  { get; }   // flat namespace; indices 0..colorCount-1
    int StackDepth      { get; }
    IReadOnlyList<int>[] TempSlotContents { get; } // flat namespace; indices colorCount..colorCount+tempSlotCount-1
    int TempSlotDepth   { get; }
    int TempSlotCount   { get; }
    int ColorCount      { get; }
    int MoveCount       { get; }
    long CurrentSequenceId { get; }                // int64; monotonically increasing (EC-12)
    GSMLifecycleState LifecycleState { get; }

    // ── Events ─────────────────────────────────────────────────────────────
    event Action<long, int> OnBoardStateChanged;               // (sequenceId, moveCount) — undo / foreground restore
    event Action<GsmSessionLoadFailReason, int> OnSessionLoadFailed; // (reason, levelId)
    event Action<int, int, int, long> OnLevelComplete;         // (levelId, moveCount, parMoves, sequenceId)
    event Action<int, int, int, int, int, long> OnLevelLoaded; // (levelId, colorCount, stackDepth, tempSlotCount, tempSlotDepth, sequenceId=0)
    event Action<long> OnBoardRefreshForced;                   // (sequenceId) — watchdog fired

    // ── Commands ───────────────────────────────────────────────────────────
    void LoadLevel(int levelId);
    void UndoRequested();
    // ExitLevel — Story 008
}
```

> **Amendment (2026-05-16)**: `OnLevelLoaded` signature is 6 params `(int levelId, int colorCount, int stackDepth, int tempSlotCount, int tempSlotDepth, long sequenceId)`. The original sketch for this ADR used 2 params `(levelId, colorCount)`. AC-GSM-20 (Story 005) supersedes the sketch — the 6-param version is the binding contract.

### Implementation Guidelines

**Board state arrays (private backing):**
```csharp
private List<int>[] _stackContents;    // flat-namespace: [color stacks... | temp slots...]
private List<int>[] _tempSlotBacking;  // views into _stackContents for TempSlotContents property
```
Inner list index 0 = bottom bolt; last index = top bolt. Never expose `List<int>` — always via `IReadOnlyList<int>`.

**Atomic 5-step mutation (TR-GSM-005):**
```csharp
private void HandleMoveCommitted(int src, int dst, int colorId, long seqId)
{
    // Step 1: Remove top bolt from source
    _stackContents[src].RemoveAt(_stackContents[src].Count - 1);
    // Step 2: Append bolt to destination
    _stackContents[dst].Add(colorId);
    // Step 3: Push undo entry
    _undoStack.Add(new UndoEntry { From = src, To = dst, ColorId = colorId, SeqId = _currentSequenceId });
    // Step 4: Increment sequence ID (BEFORE watchdog start)
    _currentSequenceId++;
    // Step 5: Increment move count
    _moveCount++;
    // Start watchdog AFTER mutation is committed
    if (_watchdogCoroutine != null) StopCoroutine(_watchdogCoroutine);
    _watchdogCoroutine = StartCoroutine(WatchdogCoroutine());
}
```

**Watchdog (TR-GSM-004) — WDG-01/WDG-02/WDG-03:**
```csharp
private Coroutine _watchdogCoroutine;
private const float WatchdogTimeoutSec = 1.5f; // 1500ms — GDD Tuning Knob; injectable for tests

private IEnumerator WatchdogCoroutine()
{
    yield return new WaitForSecondsRealtime(WatchdogTimeoutSec);
    _currentSequenceId++;
    OnBoardRefreshForced?.Invoke(_currentSequenceId);
    _watchdogCoroutine = null;
}

// Cancel on every MOVE_EXECUTING exit — IDLE, WIN, TEARDOWN, OnDestroy
private void CancelWatchdog()
{
    if (_watchdogCoroutine != null)
    {
        StopCoroutine(_watchdogCoroutine);
        _watchdogCoroutine = null;
    }
}
```

**Watchdog cancellation is mandatory on ALL exit paths:**
- Valid `OnMoveExecutingExited` arrives → `CancelWatchdog()`
- `puzzle_solved()` (WIN path) → `CancelWatchdog()`
- TEARDOWN state entry → `CancelWatchdog()`
- `OnDestroy()` → `CancelWatchdog()` (prevents DDOL coroutine leak)

**`WaitForSecondsRealtime` is required.** `WaitForSeconds` is forbidden for the watchdog — it pauses when `Time.timeScale = 0` (pause screen), causing the timer to silently stall and never fire.

**Watchdog must not start watchdog timer on the deferred undo path.** When processing a deferred undo after MOVE_EXECUTING exits, do NOT start a new watchdog — the undo is not a committed move.

**Sequence ID (TR-GSM-002):**
- Type: `long` (int64) — EC-12 forbids int16 (overflows at 32,767; reachable on undo-heavy sessions)
- Initialized to 0 at L-05 (level load)
- Increments on: BSM-01 (move commit), UND-01 (undo), WDG-01 (watchdog fire), foreground restore while in BOLT_SELECTED (SER-02)
- Never decrements

**Lifecycle FSM:**
```
UNLOADED → (load_level) → LOADING → (L-01–L-07 succeed) → ACTIVE
                                   → (any step fails)    → LOAD_FAILED → UNLOADED (auto)
ACTIVE   → (puzzle_solved)         → COMPLETE
ACTIVE   → (exit_level)            → TEARDOWN → UNLOADED
COMPLETE → (exit_level)            → TEARDOWN → UNLOADED
```

`LoadLevel` guard: `if (_lifecycleState != GSMLifecycleState.Unloaded) return;` — silent reject in all non-UNLOADED states (EC-09).

**Invariant checks (TR-GSM-007 — L-03):**
- Check 1: `sum(colorStacks[i].Length) == colorCount × stackDepth`
- Check 2: each colorId in `[1..colorCount]` appears exactly `stackDepth` times

**Deferred undo (TR-GSM-006 — EC-03):**
- Capacity: exactly 1 pending undo. Second tap while a request is already pending is silently dropped (EC-17).
- Processed on `OnMoveExecutingExited` (IDLE path only — EC-10)
- Also processed after watchdog fires (EC-11)
- Discarded on WIN path (EC-05)

**Test seam — inject timeout:** For synchronous unit tests, expose `WatchdogTimeoutSec` as a constructor/inject parameter (Story 006 guidance). `[UnityTest]` attribute with `yield return new WaitForSecondsRealtime(timeoutSec + 0.05f)` is the async alternative.

## Alternatives Considered

### Alternative 1: Observable board state via ScriptableObject channels

- **Description**: Store board state in ScriptableObject assets; systems subscribe to asset change events
- **Pros**: Designer-friendly; no MonoBehaviour dependency
- **Cons**: GC allocation per event invoke (forbidden on hot paths per ADR-0002); no coroutine support for watchdog; harder to unit test; not suitable for 60fps gameplay
- **Rejection Reason**: Performance and testability requirements rule it out

### Alternative 2: Shared mutable arrays accessible by all systems

- **Description**: `public static List<int>[] StackContents` — any system reads or writes
- **Pros**: Simplest implementation
- **Cons**: No ownership — any system can corrupt board state silently; impossible to trace mutations; undo becomes unpredictable; violates TR-GSM-001
- **Rejection Reason**: Unacceptable correctness risk

## Consequences

### Positive

- Board state is always consistent — one writer, many readers via read-only interface
- Sequence ID enables stale signal detection without polling
- Watchdog makes animation hangs recoverable without manual timeout logic per subscriber
- Atomic mutation makes undo straightforward — one undo entry per committed move

### Negative

- All Sort Mechanic moves must route through GSM events — no direct board writes
- Watchdog coroutine must be tracked and cancelled on every exit path — easy to miss

### Neutral

- Flat namespace (color stacks + temp slots in one array) requires callers to add `colorCount` offset when indexing temp slots; this is a known, documented convention

## Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|-----------|
| Watchdog coroutine leaked on DDOL object | Low | Medium — fires spuriously after level unload | `CancelWatchdog()` required in `OnDestroy()` — enforced by control manifest |
| `WaitForSeconds` used instead of `WaitForSecondsRealtime` | Low | High — watchdog silently stalls during pause | Control manifest Required pattern; unit test with pause simulation |
| Sequence ID overflow (if typed int32 and not reset per level) | Very Low | High — stale signals misidentified | Typed `long` (EC-12); resets to 0 at each level load (L-05) |

## Validation Criteria

- [ ] `StackContents` returns `IReadOnlyList<int>[]` — no cast to mutable type possible from outside GSM
- [ ] `CurrentSequenceId` never decrements across any call sequence (verified by unit test)
- [ ] Atomic 5-step mutation: all 5 steps visible in a single frame (no async gap between steps)
- [ ] Watchdog fires exactly once per stalled `move_committed` with seqId incremented
- [ ] Watchdog does not fire when `OnMoveExecutingExited` arrives within 1500ms
- [ ] No watchdog coroutine leak after level unload (no spurious `OnBoardRefreshForced` post-unload)
- [ ] `LoadLevel` rejected silently in LOADING, ACTIVE, COMPLETE states
